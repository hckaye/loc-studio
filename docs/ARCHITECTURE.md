# loc-studio の設計（実装者向けの要約）

loc-studio はゲーム向けのローカライゼーションテキスト管理ツールです。画面の左にリソースのツリー、右に多言語の表を出します。スタジオごとに違う部分は、すべてプラグインで差し替えます。この文書は実装者向けの要約で、用語はほかの文書もここに合わせています。

## 1. 設計の柱

1. リソースが正で、DB は補助です。テキスト本体はリソース（既定ではプロジェクト内のファイル）にあります。DB は進捗などのメタ情報、レビュー、変更履歴、キャッシュを持ちます。
2. 列は「値の型」と「出所」の組です。列の値は列ソースが読み書きします。本文とファイル内の列だけはフォーマット経由で読み書きします（出所 `file`）。
3. スタジオ固有の部分はすべてプラグインです。同梱機能（CSV、フォルダのツリー、ステータス列、レビュー列、DB への保存）も同じ interface の実装で、特別扱いしません。CSV は既定の CSV プラグインです。
4. アプリは固定値を持ちません。言語の一覧、ステータスやレビュー判定の選択肢、列の並びは、設定とプラグインから来ます。コアやアプリのコードに `"ja"` や `"確定"` を書きません。
5. コアはリソースを `TreeProvider` 経由でしか扱いません。ローカルにファイルを置かず、ネットワークの API から読み書きする実装にも差し替えられます。コアとサービス層は `fs` でリソースを直接読みません。
6. プラグインは実行時にフォルダから読み込みます。プラグインフォルダにコードを置けば、アプリを再ビルドせずに使えます。

## 2. パッケージ

| パッケージ | 役割 |
| --- | --- |
| `packages/sdk` | 拡張ポイント（10 種類）、ホスト機能（`PluginHost`、`HostDb`）、設定の型。プラグインとアプリの契約 |
| `packages/core` | レジストリ、プラグインの読み込み、設定、プロジェクト、列の解決、検証の実行、ロック、設定の層 |
| `packages/builtin` | 同梱プラグイン。ツリー、CSV / TSV、記法、バリデータ、列ソース（DB、レビュー）、既定のステータス列とレビュー列 |
| `packages/store` | `HostDb` の実装。SQLite（`node:sqlite`。共有モードのロックを含む）と Postgres（`pg`） |
| `packages/plugin-llm` | LLM を使う生成器（OpenAI 互換の API）。使うプロジェクトだけが設定で選ぶ |
| `packages/server` | 画面とコマンドラインが使うサービス層（フレームワークに依存しない）。行の取得、編集、保存、レビュー、履歴、検証、設定、アクション、生成。Web モードの認証と権限 |
| `apps/web` | Next.js（App Router）の画面。API は `packages/server` を呼ぶだけの薄い層。画面は React |
| `apps/desktop` | Electron の殻。Next.js の standalone ビルドを 127.0.0.1 で起動して表示する |
| `apps/cli` | コマンドライン。画面なしで検証や一括実行をする。Web モードのアカウントの管理もする |

依存の向きは次のとおりです。core、builtin、plugin-llm は sdk に依存します。store は sdk と core に依存します。server は、これらをまとめて使います。web と cli は server を使います。desktop は、web のビルドを起動するだけで、ほかのパッケージには依存しません。core は builtin と store に依存しません。

## 3. データの流れ

ツリーは `TreeProvider.list` が返すリソースの階層です。リソースの読み書きも `TreeProvider.read` / `write` で行います。

本文は `Format.parse` でエントリに分けます。編集は `Format.apply(元のバイト列, 変更点)` で変更点だけを書き戻します（ロスレス）。

リソースの版は `TreeProvider` が出します（更新時刻、ETag など）。中身と版は一緒に読みます（`readWithRevision`。なければ `revision` のあとに `read`）。書くときは読んだ版を `expectedRevision` に渡し、違えばプロバイダーが `RevisionConflictError` を投げます。サービス層は、このエラーのときだけ読み直して当て直します。ほかの失敗（認証、通信など）はやり直さずにそのまま伝えます。表示中のリソースの版の確認は、既定で 3 秒に 1 回までにします。

本文の編集は、未保存の変更（ドラフト）として積み、保存操作でリソースに書きます。ドラフトは DB に退避するので、アプリを閉じても失われません。

ファイル以外の列（ステータスなど）は、列ソースの `load` / `save` で読み書きします。同梱の `builtin.db` はホストの DB（`host.db.cells(名前空間)`）に値を置き、変更した時点で保存します（`saveMode: "immediate"`）。競合は版番号で検出します。

レビューは「列に対する投稿」です。レビュー列（`kind: "review"`、`of` で対象の列を指す）の出所は、`postReview` / `listReviews` を実装した列ソースです。同梱の `builtin.reviews` は `host.db.log(名前空間)` に追記します。セルの値は最新の投稿の判定です。投稿には、その時点の対象の値の版（`basisHash`）とユーザー名を残し、対象の値があとで変わったら「変更あり」と表示します。

変更履歴は、サービス層がセルの変更（本文の保存、列の値の変更）を `host.db.log("core.history")` に追記したものです。誰が、いつ、どのセルを、何から何へ、何をきっかけに変えたかを残します。

検証は、設定で選んだ `Validator` を本文のセルに当てます。結果はファイルに書きません。

生成列（逆翻訳など）の値は `Generator` が作ります。入力（本文の全文など）と生成器の版・パラメータを鍵に結果をキャッシュし、入力が変わったら「古い結果」と表示します。

アクション（`Action`）は、セル、行、列、選択範囲、ファイル、レビューを対象にしたボタンです。結果としてセルの変更やリンクを返します。行やリソースの値は、渡された `row` / `rows` と `host.project` から読みます（`projectRoot` のファイルを自分では読みません）。

検証は、本文のセルのほか、バリデータが名指しした列（ステータスや、ファイルの中の列）のセルにも当たります。ほかの行と比べる検証（キーの重複、訳の揺れ）は、リソース全体を受け取る `validateResource` で書きます。

フック（`WorkflowHook`）は、書き込みの前後に呼ばれます。前では理由つきで書き込みを止められ、あとではセルの変更を続けて反映できます。できごとは、列の値の変更、本文の保存、レビューの投稿、行の追加・削除、リソースの書き込みです。スタジオごとの進め方（誰がどの状態にできるか、保存したら状態を戻す、書く前にチェックアウトする）は、選択肢の `from` / `roles` の設定と、このフックで決めます。

行の追加・削除・キーの変更は、フォーマットの `apply`（`add` / `remove` / `rename`）で行い、すぐリソースに書きます。キーが変わると、未保存の編集、履歴、列ソースの値（`onEntriesChanged`）を新しいキーに移します。フォーマットが安定 ID を出していれば、アプリの外でキーが書き換えられたときも、読み込んだ時点で同じように移します。新しいリソースは `Format.create` と `TreeProvider.create` で作ります。

外部の変更は、リソースの版の確認のほか、`TreeProvider.watch` と `ColumnSource.subscribe` で受け取ります（実装があれば、プロジェクトを開いている間呼びます）。

## 4. ホストの DB（プラグインから使う）

`HostDb` は 3 種類の入れ物だけを持ちます。どれも名前空間で分かれます。

- `cells(ns)`: セルごとの値。版番号つきで、競合を検出できます。
- `log(ns)`: 追記だけの記録。新しい順の一覧と、セルごとの最新 1 件を引けます。
- `kv(ns)`: キーと値。キャッシュなどに使います。

コアの機能もこの 3 つだけで作ります（履歴は `log("core.history")`、ドラフトは `cells("core.drafts")`、生成結果は `kv("core.generated")`、本文の版は `kv("core.text-versions")` など）。SQL を書くのは `packages/store` だけです。

プロジェクトごとに DB は 2 つあります。1 つは共有 DB で、チームで共有する値（ステータス、レビュー、履歴、生成キャッシュ）を置きます。設定 `storage` で場所を決め、SQLite のファイル（`storage.path`）か Postgres（`storage.driver: "postgres"`、`url`、`schema`）を選べます。もう 1 つはその PC の DB で、アプリデータ内の SQLite にドラフトを置きます。検証の結果はメモリ上にキャッシュし、画面の状態（列の幅、表示する言語など）はブラウザの `localStorage` に置きます。共有 DB の SQLite をネットワーク上に置く場合（`storage.sharing.mode: "lockfile"`）は、WAL を使わず、書き込みをロックファイルで 1 人ずつにします。

## 5. 設定

プロジェクト設定はチーム共通の設定で、`loc-studio.project.json`（画面から変える値）と `loc-studio.config.ts`（コードで書く部分）に書きます。両方にある項目は `loc-studio.config.ts` が優先します。

ローカル設定はその PC だけの設定で、アプリデータ内の `settings.json` に書きます。ユーザー名（既定は PC 名）、テーマ、レビューの転載などです。Web モードでは、ローカル設定の代わりに利用者ごとの設定をサーバーの DB に置きます。

値の優先順位は、プロジェクト設定の `localSettings.enforce`（固定）、起動引数と環境変数、ローカル設定、`localSettings.defaults`、アプリの既定値の順です。秘密情報とプラグインの信頼は固定できません。

実装は名前（id）で登録し、設定は `use` で選びます。実装に渡す値は、呼び出し時の `options` です。列は、`columns` に列の定義そのものか `{ use: "<プラグインが登録した列の id>", ...上書き }` を並べます。省略すると「キー」「本文」の 2 列だけになります。

## 6. プラグインフォルダ

プラグインは次の順に探し、後ろほど優先します: `<アプリのフォルダ>/plugins/`、環境変数 `LOC_STUDIO_PLUGIN_DIRS`、`<プロジェクト>/loc-studio-plugins/`、`<アプリデータ>/plugins/`。プラグインは単一ファイル（.ts / .js / .mjs など）か、`plugin.json` を持つフォルダです。TypeScript もそのまま読み込みます。

### 6.1 プラグインの信頼

プロジェクトを開くと、プラグインフォルダのコードとコードの設定（`loc-studio.config.*`）が動きます。設定ファイル（`loc-studio.project.json`）は、保存先、プラグインのフォルダ、外部の接続先、使う環境変数を決めます。画面のローカルモード（サービス層の `pluginTrust: "prompt"`、既定）では、次の 3 つを、利用者が信頼するまで使いません。project 層と local 層のプラグイン、コードの設定、設定ファイルの基盤の項目（`storage`、`pluginDirs`、`tree`、`formats`、`syntaxes`、`sources`、`generators`、`actions`、`hooks`、`review` と、参照する環境変数の名前）です。

信頼は、中身のハッシュでローカル設定 `plugins.trust` に残し、中身が変わったら確認し直します。コードのハッシュに入るのは、読み込むと実行されうるファイルです。フォルダのプラグインはフォルダの全ファイル、単一ファイルとコードの設定はそのファイルと相対 import でたどれるファイルです（`packages/core/src/code-graph.ts`）。import は構文解析で見つけ、読み込むファイルを前もって決められない書き方（引数を計算する `import()` や `require`、`createRequire` など）と、基準のフォルダの外に出る import は断ります。単一ファイルとコードの設定では、たどれないコードを動かせる書き方（`eval`、`Function`、`vm` や `child_process` の読み込みなど）も断ります。この検査はサンドボックスではなく、信頼したコードは実行時に何でもできます。

設定ファイルを信頼していない間と、コードの設定を信頼しておらず JSON の設定だけでは開けない間は、制限された状態で開きます。この状態では、環境変数を展開せず、DB を開かず、ネットワークに接続せず、コードも読み込みません。builtin 層と app 層は常に読み込みます。コマンドラインと Web モードは `"always"`（すべて確認なしで使う）です。Web モードは local 層を読みません。

### 6.2 Web モード

Web モードは、複数人が 1 つのサーバーをブラウザから使うモードです（[WEB-MODE.md](WEB-MODE.md)）。`packages/server` の `openServerRuntime` が、サーバーの DB（アカウント、セッション、権限、利用者ごとの設定）、認証（`openAuthService`）、プロジェクトごとのワークスペースをまとめます。Web の層は、認証したあと `runtime.handle({ projectId, method, params, user })` を呼ぶだけです。権限はサービス層が確かめ、足りなければ `forbidden` を返します。メソッドごとに必要な権限は `METHOD_CAPABILITIES` の表で決まり、役割ごとにできることは、プロジェクトの役割の定義で決まります（同梱の viewer / translator / reviewer / manager に、設定の `roles` を重ねたもの）。役割は、触れる列、実行できるアクション、見えるリソースを絞れます。見えないリソースは、どの読み出しでも「ない」ものとして扱います。役割は名前ではなく権限（`can`）で判断するので、コードに役割の名前での分岐はありません。プロジェクト設定のうち、コードの実行やファイルと DB の場所に関わる項目は、サーバーの管理者（`CallContext.admin`）だけが変えられます。呼び出しの間の記録は、その利用者の名前で残ります（AsyncLocalStorage）。プロジェクト設定の `${env:}` とプラグインに見せる環境変数はサーバーの設定で許した名前だけで、管理者でない利用者に返す値からはサーバーのパスを伏せます（`redact.ts`）。

### 6.3 独自描画（CellRenderer）

プラグインは `renderers: [{ id, module }]` で、ブラウザで動く ES モジュールを登録できます。サーバーはそのファイルだけを配り（`Workspace.rendererModule`）、画面は実行時に `import()` します（アプリの再ビルドは要りません）。列は `renderer` で独自描画を選び、`display`（`link` / `progress` / `color` / `tags`）で同梱の見せ方を選びます。拡張ポイントは、サーバー側で動く 9 種類（tree、format、syntax、source、column、generator、action、validator、hook）と、この renderer を合わせた 10 種類です。

## 7. 画面（`apps/web`）

配色はライトテーマが既定です。背景 #ffffff、パネル #f4f5f7、線 #dde1e6 / #c4cad2、文字 #1b1f24、補助の文字 #57606a、アクセント #1a63d6、注意 #8a5300（地 #fdf2dc、線 #e3b866）、エラー #b3361a（地 #fde9e2）、良好 #17754f、選択 #e3ecfb。フォントは Noto Sans JP 系のシステムフォントで、UI は日本語です。

レイアウトは、上にバー、左にリソースのツリー（進捗率と未保存の印）、右にツールバーと表、下にステータスバーです。

表の 1 行は 1 エントリです。列は、共通グループ（キーなど entry スコープの列）と、言語グループ（言語ごとに、本文とその言語の列）に分かれます。共通グループは左端に固定し、言語グループも見出しのピンで固定できます。行と列の両方向を仮想化しています。サービス層の `rows` は、5 万行のリソースでページの取得が 500 ミリ秒未満になることをテストで確かめています（`packages/server/src/perf.test.ts`）。

言語は 16 以上を想定しています。ツールバーの「言語 3 / 16」のボタンから選択パネル（検索、グループ、表示セット、言語ごとの表示チェックとピン）を開きます。表示中の言語だけを読み込みます。

本文はセルの中では編集しません。ダブルクリック（または Enter / F2）で編集モーダルを開きます。左に参照（基になる言語の本文、生成列）、右に編集欄（文字数、検証結果、該当箇所の下線）、下にその言語の列（ステータスなど）とレビューの現在値、「レビューを投稿」があります。Enter は改行、確定は Ctrl+Enter、確定して次の行は Alt+↓、取消は Esc です。確定すると未保存の変更として表に戻り、Ctrl+S でリソースに書きます。

選択式の列（enum）は、セルのドロップダウンで選びます。選択肢は列の定義から来ます。レビュー列は、ドロップダウンで判定を選ぶと投稿パネルが開き、コメントを書いて投稿します（選択肢に `requireComment` があればコメントは必須）。パネルには、これまでの投稿と、対象の値が変わった印が出ます。アクション列は、アクションのボタンが並ぶ専用の列です。

セルには、未保存、検証の問題（理由つき）、要再確認（基になる言語の本文が変わった）、対象の値が変わったレビュー、古い生成結果の印が付きます。

ツールバーには、検索、列の値での絞り込み（選択式の列は値、文字や数値の列は「含む」）、「未翻訳のみ」「問題あり」（数える重さを選べる）「要確認」「未保存」、行の追加・キーの変更・削除のメニュー、言語の切り替え、保存があります。ツリーの上には、リソースを作るボタンがあります。編集モーダルの参照欄に並べる言語と列、本文の長さの数え方、ツリーに進捗を出す列は、設定（`editor`、`grid.progressColumn`）で変えられます。詳細パネルは、選択した行の全言語、検証結果、変更履歴、レビューの投稿を出します。設定の画面は、プロジェクト設定とローカル設定（Web モードでは個人設定）を分けています。固定された項目は変更できないと表示します。プラグインのダイアログは、読み込んだプラグイン、層、エラーを出し、再読み込みができます。

Web モードでは、ログイン、プロジェクトの一覧、利用者のメニュー、管理の画面が加わり、権限のない操作のボタンは理由つきで無効になります。

信頼の確認のダイアログは、コードの設定とプラグインをまとめて並べ、種類、確認の対象のファイル、ハッシュの先頭を出します。コードの設定を信頼しておらず JSON の設定だけでは開けないプロジェクトは、このダイアログと「プロジェクトを閉じる」だけの画面で開きます。プラグインから来たリンクは、`http` と `https` の URL のときだけクリックできます。

サーバーは起動の仕組み（`apps/web/scripts/launch.mjs`）を通して起動します。起動の仕組みはモード、待ち受けるアドレス（`LOC_STUDIO_HOST`、既定 127.0.0.1）、Web モードの設定を確かめ、ローカルモードでは起動ごとの合言葉を作って `?token=…` 付きの URL を表示します。すべての要求の入口（`apps/web/proxy.ts`）は、ホスト名の許可リスト（違えば 421）とローカルモードの合言葉のクッキー（なければ 401）を確かめ、ページには要求ごとの nonce を使った CSP、API には `default-src 'none'` の CSP と、`X-Frame-Options: DENY` などのヘッダーを付けます。各 API の口は、本文を読む前に認証とオリジン（`Sec-Fetch-Site`、`Origin`）を確かめ、本文の大きさを制限します。詳しくは [WEB-MODE.md の 10.1](WEB-MODE.md#101-http-の口appswebappapi) にあります。

## 8. 決め打ちにしているもの

スタジオごとに違うものと、進め方に合わせて変えたくなるものは、設定とプラグインに出しています（[AGENTS.md](../AGENTS.md#スタジオごとに違うものをアプリのコードに決め打ちしない)の表）。次のものは、いまはアプリのコードで決めています。ここにない決め打ちを足すときは、この表にも足します。

| 決め打ちにしているもの | 内容 | 変えたいときの手段 |
| --- | --- | --- |
| 本文の列は 1 つ | 最初の `kind: "text"` の列だけを本文として扱う。未保存の編集、検索、未翻訳の判定は、この列が対象 | 言語ごとに複数の文字列が要るときは、言語ごとの列（`kind: "meta"`、`scope: "language"`）を足す |
| 要再確認の判定 | 訳文を保存したあとで、基になる言語（`basedOn`。1 段）の本文が変わったら印を付ける。印を付けるかどうかは、設定の `validation.recheck` で選べる | 別の条件で状態を戻したいときは、`validation.recheck` を `false` にして、フックの `after` で列の値を変える |
| 未翻訳の絞り込み | 本文が空の行。「原文と同じ」などは含めない | 別の定義は、バリデータの問題にして「問題あり」で絞り込む |
| レビューの形 | 判定（選択肢）とコメント。返信、解決済みの状態、添付はない | 外部のチケットに持つなら、レビュー列の列ソースと転載先のアクションを書く |
| 列の値の型 | 文字列、数値、真偽値、日付、選択式。選択肢は設定に書く | 担当者などは、文字列の列と独自描画で扱う |
| 進捗の数え方 | 行数、原文の文字数、原文の語数（空白で区切った数）のどれか（設定の `grid.progressUnit`）。語の区切りは空白だけで、日本語や中国語の語は数えられない | なし |
| ファイルの中の列の書き込み | 変更した時点でリソースに書く（本文だけが、未保存の変更を経て保存される） | なし |
| 役割の権限の種類 | `edit` / `review` / `run` / `structure` / `manage` の 5 つ | 役割の絞り込み（列、アクション、リソース）と、選択肢の `roles` で細かくする |
| 共有 DB | SQLite か Postgres | なし |
| 認証 | パスワードか、前段のプロキシが渡す利用者名 | SSO は、前段のプロキシで行う |
| Web モードの秘密情報 | サーバーの環境変数だけ（利用者ごとには持てない） | なし |
| 上限と間隔 | 1 回に返す行数（2000）、ジョブの数（利用者ごと 3、ワークスペースごと 20）、ジョブにする行数（20 行を超えるアクション）、版の確認の間隔（3 秒）など | コードの定数 |
| 画面の言語 | 日本語（画面の文言と、エラーの文言） | なし |
| 同梱の CSV の文字コード | UTF-8、UTF-16、Shift_JIS（フォーマットの `encoding`）。Shift_JIS は自動では見分けない | ほかの文字コード（EUC-JP、GB18030 など）は、フォーマットのプラグインを書く |
