# 条件での絞り込み、検索ビュー、集計と書き出し

行を条件で絞り込み、どのリソースにどれだけ残っているかを数え、結果を CSV に書き出す方法をまとめます。条件は、画面の「条件」で選んで組み立てることも、式で書くこともできます。同じ条件を、コマンドライン（`loc-studio query`）とサービス層（`rows` / `query` の `where`）でも使えます。

## 画面での使い方

### 条件を選んで組み立てる

ツールバーの「条件」を押すと、条件を組み立てる窓が開きます。1 つの条件は、次の 4 つを選んで作ります。

| 選ぶもの | 内容 |
| --- | --- |
| 欄 | プロジェクトの列（本文、ステータス、レビューなど）と、下の「組み込みの欄」 |
| 言語 | 言語ごとの欄のとき。1 つの言語か、「表示中のどれかの言語」「表示中のすべての言語」 |
| 比べ方 | 欄の種類によって変わる。選択式の列は「次と同じ」「次以上」など、文字の列は「次を含む」「空」など |
| 値 | 選択式の列と問題の重さは、選択肢から選ぶ。文字、数、日付は入力する |

「条件を足す」で条件を増やし、「条件のつなぎ方」で、すべての条件に合う行か、どれかの条件に合う行かを選びます。「この条件で絞り込む」を押すと、サーバーが式を確かめてから表に当てます。誤りがあれば、その説明を窓の中に出し、表は変えません。

よく使う条件は、次のように組み立てます。

| 見つけたい行 | 欄 | 比べ方 | 値 |
| --- | --- | --- | --- |
| 未レビューの行 | レビューの列 | 次と同じ | 未レビューの選択肢 |
| 本文が確定している行 | ステータスの列 | 次と同じ | 確定の選択肢 |
| 本文が空の行 | 本文の列 | 空 | なし |
| 本文に問題のある行 | 検証の問題 | 次以上 | 警告（またはエラー） |
| 原文が変わったあと見直していない行 | 要確認 | である | なし |

選択肢の名前と値は、プロジェクト設定の列の `type.enum` で決まります。上の表の「未レビュー」「確定」は、同梱の列の選択肢の名前です。

### 式で書く

窓の上の「式で書く」に切り替えると、条件を式で書けます。組み立てた条件があれば、その式が入った状態で始まります。かっこを使った入れ子の条件や、否定（`not`）は、式で書きます。

入力に合わせて、その場所に書けるものの候補が出ます。欄を書く場所では欄、`列@` のあとでは言語、欄のあとでは比べ方、比べ方のあとでは値（選択式の列の選択肢、問題の重さ）、条件のあとでは `and` と `or` です。↑ と ↓ で選び、Enter か Tab で入れます。Ctrl+Space で、候補をもう一度出せます。

### ツリーの件数

絞り込んでいるあいだは、左のツリーの各リソースに、条件に合う行の数が出ます。フォルダには、中のリソースの合計が出ます。ツリーの上には全体の合計が出て、「該当ありだけ」にチェックを入れると、合う行のないリソースを隠せます。

件数は、表と同じ条件で数えます。検索欄、列の値の絞り込み、「未翻訳のみ」「問題あり」「要確認」「未保存」、条件のどれを使っていても数えます。対象の言語は、表示中の言語です。

### 検索ビュー

ツールバーの「検索ビュー」を押すと、表の代わりに、いまの絞り込みに合う行をプロジェクトのすべてのリソースから集めた表が出ます。

- 上に、条件に合う行の数、対象の行の数、合う行のあるリソースの数、原文の文字数と語数が出ます。
- 「集計」で区切りの欄を選ぶと、その欄の値ごとの行数と原文の量が出ます。区切りは 2 つまで選べます。選べるのは、選択式の列、検証の問題、問題の種類、要確認、未保存、リソースです。
- 「結果を CSV に保存」で、条件に合うすべての行を CSV のファイルに保存します。「結果をコピー」は、タブ区切りでクリップボードに入れるので、表計算ソフトにそのまま貼り付けられます。集計も、同じように保存とコピーができます。
- 結果の行を押すと、絞り込みを保ったまま、そのリソースの表に戻り、その行が選ばれます。

結果の表は、200 行ずつ読み込みます（「続きを表示」）。CSV への保存とコピーは、読み込んだ分だけでなく、条件に合うすべての行が対象です。

原文の量は、最初の原文の言語（`basedOn` のない最初の言語）の本文で量ります。文字数はコードポイントの数、語数は空白で区切った数です。

### 一括アクション

絞り込みに合う行すべてに、アクション（[plugins/action.md](plugins/action.md)）をまとめて実行できます。「一括アクション ▾」は 2 か所にあります。

- 表のツールバーの「一括アクション ▾」は、開いているリソースの、いまの絞り込みに合う行が対象です。絞り込みがなければ、そのリソースのすべての行です。
- 検索ビューの「一括アクション ▾」は、プロジェクト全体の、条件に合う行が対象です。条件に合う行のあるリソースを、順に回して実行します。

メニューに出るのは、行が対象のアクション（`target` が `cell` / `row` / `selection`）です。セルが対象のアクションは、列と、表示中の言語の組ごとに並びます（例: 「前後の空白を削除（日本語 / 本文）」）。ファイルや列の全体が対象のアクション（`file` / `column`）は、これまでどおり、ツールバーの「アクション ▾」と列見出しのメニューから実行します。

アクションを選ぶと、対象の行数を出して確かめます。「○ 行に実行」を押すまでは、何も実行しません。実行中は、済んだリソースの数が出て、「中止」で止められます（中止すると、次のリソースには進まず、動いているジョブを取り消します。すでに済んだ変更は戻りません）。終わると、条件に合った行の数、反映した変更の数、エラーの数と内容が出ます。

- 行を選ぶのはサーバーです。確かめる窓に出る行数は、押した時点の数で、実行のときに条件に合う行を数え直します。
- 1 つのリソースで条件に合う行が 20 行を超えると、そのリソースの分はジョブになります。ジョブが終わるのを待ってから、次のリソースに進みます。
- アクションが本文を変えたときは、未保存の変更になります（保存するまで、ファイルには書きません）。ステータスなどの列の値は、すぐに変わります。
- 実行できるのは、アクションを実行できる役割だけです（Web モード）。役割で見えないリソースは、対象に入りません。
- 画面を閉じると、まだ回していないリソースには実行されません。大量の行に確実に実行したいときは、コマンドラインの `run --where` を使います（下）。

### お気に入り

ツールバーの「お気に入り」で、いまの絞り込みと並べ替えに名前を付けて覚えられます。覚えるのは、検索欄、列の値の絞り込み、切り替え、条件、並べ替え、検索ビューを開いているかどうかと集計の区切りです。「列と言語の表示も覚える」にチェックを入れると、隠している列と表示中の言語も覚え、選んだときに戻します。同じ名前で保存すると、上書きします。

お気に入りは、その PC に保存します（Web モードでは、利用者ごとにサーバーに保存します）。ほかの人とは共有しません。

### 列の表示

ツールバーの「列」で、列ごとに表示するかを選べます。キーの列は、いつも表示します。言語ごとの列を隠すと、すべての言語で隠れます。いまの表示に名前を付けて、プリセットとして覚えられます。言語ごとの表示の切り替えは、となりの「言語」で行います。

### 開き直したときの復元

アプリやページを開き直すと、前回の状態に戻ります。戻すのは、開いていたリソース、絞り込み（条件を含む）、並べ替え、検索ビューを開いていたかどうかと集計の区切り、選んでいたセル、スクロールの位置、ツリーの見え方（たたんだフォルダ、名前での絞り込み、「該当ありだけ」）、隠した列、表示する言語、列の幅、表示密度、詳細パネルを開いていたかどうかです。編集の途中の入力と、開いていたダイアログは戻しません。

前回のリソースがなくなっていたら、最初のリソースを開きます。前回の絞り込みや並べ替えが、いまの設定に合わなくなっていたら（列がなくなったなど）、外してその旨を知らせます。

状態は、プロジェクトごとに、その PC の DB（個人の設定フォルダの `projects/<プロジェクトごとのフォルダ>/local.db`）に保存します。Web モードでは、利用者ごとに分けて保存します。操作のあと 0.4 秒ほどで保存するので、操作の直後にアプリを強制終了すると、最後の操作の分は残らないことがあります。

## 条件式の書き方

```
textStatus@ja = done and (text@en is empty or issues@en >= warning)
```

### 欄

| 書き方 | 意味 |
| --- | --- |
| `列 ID` | 行に 1 つの列（例: `maxLength`） |
| `列 ID@言語 ID` | 言語ごとの列の、その言語の値（例: `text@en`） |
| `列 ID@any` | 対象の言語のどれか（`列 ID@*` と書いても同じ） |
| `列 ID@all` | 対象の言語のすべて |
| `列 ID`（言語ごとの列で、`@` を省く） | `列 ID@any` と同じ |

対象の言語は、画面では表示中の言語、コマンドラインでは `--languages`（省略時はすべての言語）、サービス層では要求の `languages` です。対象の言語にその列が 1 つもなければ、`@any` も `@all` も合いません。

列の ID は、プロジェクト設定の `columns` の `id` です。アクション列は値を持たないので、条件に使えません。

### 組み込みの欄

同じ ID の列がプロジェクトにないときに使える欄です。`key` と `resource` 以外は、列と同じように `@言語 ID`、`@any`、`@all` を付けられます。言語を付けないと、対象の言語のすべての列と、行に 1 つの列をまとめて見ます。

| 欄 | 値 |
| --- | --- |
| `key` | 行のキー |
| `resource` | リソースのパス |
| `issues` | 検証の問題のうち、いちばん重いもの。`none`、`info`、`warning`、`error` のどれか |
| `issueCode` | 検証の問題の種類（バリデータが返す `code`）。その行にある種類のどれかと比べる |
| `stale` | 要確認の印があるか（レビューや生成のあとで対象の本文が変わった、原文が変わった） |
| `unsaved` | 未保存の本文があるか |

### 比べ方

| 書き方 | 意味 |
| --- | --- |
| `=`、`!=` | 同じ、違う |
| `<`、`<=`、`>`、`>=` | 大小 |
| `~`、`!~` | 含む、含まない（大文字小文字を区別しない） |
| `is empty`、`is not empty` | 値が空、空でない |
| `in (a, b)`、`not in (a, b)` | どれかと同じ、どれとも違う |
| 欄だけを書く | `stale`、`unsaved` は「である」。`issues` は「問題がある」。列は、値が空でなく `false` でもない |

比べ方は、欄の種類に合わせて働きます。

- 選択式の列は、値でも表示名でも書けます（`textStatus@ja = done` と `textStatus@ja = 確定` は同じ）。値のないセルは、列の `type.default` の値として扱います。大小は、設定に書いた選択肢の並び順です。ない選択肢を書くと、選べる値を添えて断ります。
- 数は、数の大きさで比べます。列の値が数として読める文字列のときも同じです。引用符で囲んだ値（`"12"`）は、文字として比べます。
- 文字の `=` は、完全に一致するときだけ合います（大文字小文字を区別します）。大小は、文字の順です（文字の中の数字は、数として比べます）。日付の列は `2026-11-15` の形の文字列なので、大小がそのまま日付の前後になります。
- 空の値は、大小の比較には合いません。
- `issues` は、`none`、`info`、`warning`、`error` の順で比べます（`issues@en >= warning`）。
- `issueCode` は、`=`、`!=`、`~`、`!~` だけが使えます。

### 値

空白や記号（`( ) , " ' = < > ~ !`）を含む値、空の値、予約語（`and`、`or`、`not`、`is`、`in`、`empty`）は、引用符（`"` か `'`）で囲みます。引用符の中では、`\"` で引用符、`\\` でバックスラッシュ、`\n` で改行を書けます。

### つなぎ方

`and`、`or`、`not` と、かっこでつなぎます。`and` は `or` より先に結び付きます。`not` は、その次の条件（か、かっこの中）だけに掛かります。条件を並べるときは、`and` か `or` を省けません。

```
textStatus@ko = done or key ~ "choice" and text@ko is empty
```

この式は、「韓国語のステータスが done」または「キーに choice を含み、韓国語の本文が空」の行に合います。

### 例

| 見つけたい行 | 式 |
| --- | --- |
| どれかの言語が未レビュー | `reviewStatus = none` |
| 英語が確定していて、韓国語の本文が空 | `textStatus@en = done and text@ko is empty` |
| どれかの言語にエラーがある | `issues >= error` |
| 変数の過不足の問題がある | `issueCode ~ placeholder` |
| すべての言語が承認済み | `reviewStatus@all = ok` |
| 上限が 10 以上で、確定していない | `maxLength >= 10 and not textStatus@ja = done` |
| システムのフォルダのリソースで、未保存がある | `resource ~ "system/" and unsaved` |

ここに出てくる列の ID（`textStatus`、`reviewStatus`、`maxLength`）と値（`done`、`none`、`ok`）は、サンプルのプロジェクトのものです。自分のプロジェクトでは、設定の列の ID と選択肢の値を書きます。

### 誤りの知らせ方

式に誤りがあると、何が違うかを添えて断ります（サービス層では `invalid`、コマンドラインでは終了コード 2）。

- 書き方の誤りは、位置を添えます（「条件式の 11 文字目: "=" のあとに値がありません」）。
- ない列を書くと、使える列と組み込みの欄を並べます。
- 選択式の列にない値を書くと、選べる値を並べます。

## コマンドライン

`loc-studio query` で、同じ条件を使って数え、集計し、書き出せます。オプションと出力の例は [CLI.md の query](CLI.md#query) にあります。

```sh
# どのリソースに、エラーのある行がどれだけあるか
node apps/cli/dist/index.js query --project examples/sample-project --where "issues >= error"

# 韓国語のステータスごとの、行数と原文の量
node apps/cli/dist/index.js query --project examples/sample-project --group-by textStatus@ko

# 韓国語の本文が空の行を、CSV に書き出す
node apps/cli/dist/index.js query --project examples/sample-project --where "text@ko is empty" --format csv --columns text@ja,text@ko --out untranslated.csv --bom
```

`loc-studio run <アクション> --where <式>` は、同じ条件に合う行だけに、アクションを実行します（画面の「一括アクション」と同じ。[CLI.md の run](CLI.md#run)）。先に `query --where` で同じ式を試すと、対象になる行を確かめられます。

## 書き出しの形

- 行の書き出しの見出しは、`resource`、`key`、続けてセルの ID（`text@ja` など）です。選択式の列は、表示名ではなく値を書きます。
- 集計の書き出しの見出しは、区切りの欄、`rows`、`characters`、`words` です。
- CSV はカンマ、TSV はタブで区切ります。区切り文字、引用符、改行を含む値と、前後に空白のある値は、引用符で囲みます（中の引用符は 2 つ重ねます）。行の終わりは CRLF です。
- 文字コードは UTF-8 です。画面の「CSV に保存」は、表計算ソフトが文字コードを見分けられるよう、先頭に BOM を付けます。コマンドラインは、`--bom` を付けたときだけ BOM を付けます。
- 値は、そのまま書きます。`=` や `+` で始まる値を、表計算ソフトが数式として読むことがあります。信頼できない人が本文を書き込めるプロジェクトの書き出しを開くときは、注意してください。
- 1 回の書き出しは 200,000 行までです。超えたら打ち切り、その旨を知らせます。

## 確かめたこと

- 条件式の解釈、リソースをまたぐ問い合わせ、集計、CSV / TSV の書き出しは、サンプルのプロジェクトに対するテスト（`packages/server/src/query.test.ts`）で確かめています。
- 画面の操作（条件の組み立て、式の補完、誤った式の扱い、ツリーの件数、検索ビュー、CSV の保存、列の表示、開き直したあとの復元）は、本番ビルドのサーバーに Chrome でつないで確かめています（`npm run check:browser`）。スクロールの位置の復元は、横の位置だけをブラウザで確かめました。縦の位置は、コンポーネントのテストで確かめています。
- 「一括アクション」は、検索ビューから 2 行に実行して、条件に合う行だけが変わることと、表のツールバーのメニューに対象の行数が出ることを、ブラウザで確かめています（`npm run check:browser`）。ジョブになる行数（20 行を超える）での実行、「中止」、複数のリソースをまたぐ実行は、コンポーネントとサービス層のテストで確かめただけで、ブラウザでは操作していません。
- 「結果をコピー」（クリップボード）は、コンポーネントのテストで確かめただけで、ブラウザでは操作していません。
- デスクトップ版で、アプリを起動し直したあとに、前回開いていたリソースと絞り込みが戻ることは、Windows の配布物を 2 回起動して確かめています（`npm run check:desktop`）。起動のたびに内部サーバーのポートが変わっても戻ります。デスクトップ版での「CSV に保存」（保存先を選ぶ窓）と「結果をコピー」は、操作していません。
