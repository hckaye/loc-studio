# @loc-studio/plugin-llm の設計

`@loc-studio/plugin-llm` が守っている決まりと、その決まりから出てくる動きをまとめます。理由を書いた箇所は、ソースのコメントか、ほかの文書（[AGENTS.md](../../../AGENTS.md)、[plugins/settings.md](../../plugins/settings.md)）に書かれているものです。実装の細部は [implementation.md](implementation.md)、設定に書ける値は [settings.md](settings.md) にあります。

## アプリとの境目

このプラグインは、生成器 2 つと、それを使う列 2 つ、プラグインの設定 4 つを登録するだけです。DB には触らず、画面も持ちません。次のことは、どれもアプリ（サービス層と画面）の側にあり、生成器の拡張ポイントを使うほかのプラグインと共通です。

| すること | 担当 |
| --- | --- |
| どのセルを生成するかを決める（範囲、条件、言語） | サービス層 |
| 結果を共有 DB に残す、キャッシュを引く、「変更あり」を判定する | サービス層 |
| 入力をまとまりに分ける、同時に送る、失敗をやり直す、ジョブとして進み具合を出す | サービス層（数は、生成器が既定を持つ） |
| 権限を確かめる（Web モードで、誰が生成できるか） | サービス層 |
| セルごとの入力を作る、モデルに送る、返事を結果にする | このプラグイン |
| プロンプトなどの入力欄を出す、保存する | 設定の画面（プラグインの設定の仕組み） |

`packages/plugin-llm` が依存するのは、SDK（`@loc-studio/sdk`）だけです。コアにもサービス層にも依存しません。サービス層とコマンドラインが、`@loc-studio/builtin` と並べて、プロジェクトを開くときに登録します。登録されるだけでは外部に接続せず、プロジェクトが設定の `generators` と `columns` で選んだときにだけ使われます。

アプリのコードに、このプラグインのための分岐はありません（このプラグインの名前が出てくるのは、登録の 2 か所、コマンドラインの使い方の説明、画面のビルドの設定（`apps/web/next.config.mjs` の、サーバー側のパッケージの一覧）と、コメントだけです）。評価の判定を色つきの札で出すのは、生成列の `type` が選択式なら選択肢の色で出す、という生成列に共通の動きです。理由を横に出すのも、生成器が結果に添えた説明（`comment`）を出す、共通の動きです。

## 値の置き場所を 4 つに分けている

| 値 | 置き場所 | そこに置く理由 |
| --- | --- | --- |
| 接続先（`endpoint`、`model` など） | プロジェクト設定の `generators` の `options` | 外部につなぐ値なので、信頼の確認の対象にする。Web モードでは、サーバーの管理者だけが変えられる |
| プロンプト、訳し先、比べる原文の言語 | プラグインの設定 | スタジオが、画面から調整する値。Web モードでは、`manage` の権限がある役割が変えられる |
| API キー | 秘密情報 | 設定ファイルはプロジェクトのフォルダにあり、チームで共有されるので、そこには置かない |
| まとめて送る件数 | 生成を実行するときに選ぶ | 外部に送る操作は、1 回にまとめる数を、実行する人が選べるようにする。生成器は、既定（1 件ずつ）を持つだけにする |

接続先をプラグインの設定に置かないのは、プラグインの設定が、Web モードで `manage` の役割から変えられるためです。接続先を変えられると、本文を、設定を変えた人の用意したサーバーに送らせることができます。基盤の項目（`generators`）に置くと、画面のローカルモードでは信頼の確認が出て、Web モードでは管理者だけの項目になります。

プロンプトと訳し先は、プラグインの設定と、生成器の `options` の両方に書けます。プラグインの設定は、プラグインごとに 1 組の値です。`options` は、使う場所ごとの値です。同じ生成器を、列ごとに別の訳し先で使うときのために、`options` の値を優先します。

## 生成器の形

### 1 つのセルの入力

- `llm.translate` の入力は、そのセルの言語の本文です。空の本文は、生成しません。
- `llm.evaluate` の入力は、そのセルの言語の本文（訳文）と、原文の本文です。原文の言語が決まらないセル、原文の言語そのもののセル、原文か訳文が空のセルは、生成しません。

評価は、原文を入力に入れています。サービス層は、入力が変わると結果を「変更あり」にするので、訳文だけでなく、原文が変わったときも「変更あり」になります。

比べる原文の言語は、既定では、評価する言語の `basedOn` です。言語の ID をコードに書かず、プロジェクトの言語の定義から決めています。

### キャッシュの鍵

サービス層は、生成器の ID、`version`、`cacheParams` の値、入力の全文を鍵にして、結果を残します。`cacheParams` には、結果が変わる値だけを入れます。

- 接続先とモデル、`temperature`、プロンプト、訳し先、`instructions` は入れます。変えると、生成し直せるようになります。
- API キーの秘密情報の名前と、制限時間は入れません。変えても、結果は変わらないためです。
- `llm.translate` は、プロンプトが既定のままのときは、プロンプトを鍵に入れません。プロンプトを設定に出す前に作った結果を、そのまま使えるようにするためです。

### 1 件ずつ送るときと、まとめて送るとき

生成器の `run` は、サービス層がまとめた入力の配列を受け取ります。件数で、送り方を変えます。

| | 1 件 | 2 件以上 |
| --- | --- | --- |
| 機械翻訳の本文 | 本文そのまま | `id` を付けた JSON の配列 |
| 機械翻訳の返事 | 返事の全体を、翻訳として使う | `id` ごとの翻訳の、JSON の配列 |
| 評価の本文 | 原文と訳文の JSON | `id` を付けた組の、JSON の配列 |
| 評価の返事 | 判定と理由の JSON | `id` ごとの判定と理由の、JSON の配列 |

機械翻訳の 1 件のときは、JSON を使いません。本文をそのまま送り、返事をそのまま結果にするので、返事の形を読む処理を通りません。既定を 1 件ずつにしているのは、[AGENTS.md](../../../AGENTS.md#絞り込みと画面の状態を足す変えるとき) の決まり（同梱の LLM の生成器の既定は、1 件ずつ）です。

まとめて送るときは、返事を `id` で入力と結び付けます。返事の配列の順には頼りません。`id` が足りない、同じ `id` が 2 回ある、配列でない返事は、そのまとまり全体を失敗にします。失敗したまとまりは、サービス層が、生成器の `retries`（2 回）までやり直します。

### 返事の読み方

モデルの返事は、指示どおりの形とは限りません。次の 2 つは、受け入れます。

- コードの囲み（```` ```json ```` と ```` ``` ````）で包んだ JSON。
- JSON の前後に、文章が付いた返事（最初のかっこから、最後のかっこまでを読む）。

次のものは、受け入れずに失敗にします。

- JSON として読めない返事。
- 評価の判定が、`OK`、`WARNING`、`NG` のどれでもない返事（大文字と小文字の違いは、そろえて受け入れます）。
- 翻訳が空の返事、結果のない応答。

失敗にした返事は、結果として残りません。評価の列に入る値は、列の選択肢と同じ 3 つの値だけになります。

### 失敗の知らせ方

失敗の文言は、どれも生成器の ID で始め、理由を入れます。接続と応答の失敗（接続できない、制限時間、HTTP のエラー、応答の形）には、接続先の URL も入れます。接続先の応答の本文は、先頭の 300 文字だけを入れます（長い HTML のエラーページなどを避けるためです）。API キーは入れません。設定が足りないとき（`endpoint` か `model` がない）は、設定に何を書けばよいかを、文言に書きます。

要求は、呼び出し側の中断（ジョブの取り消し）と、制限時間のどちらでも止まります。取り消しで止まったときは、失敗の文言に作り直さず、元の中断をそのまま伝えます。

## このプラグインの中で決めているもの

[ARCHITECTURE.md の 8 章](../../ARCHITECTURE.md#8-決め打ちにしているもの)の「同梱の LLM のプラグインの既定」に当たります。アプリのコードではなく、このプラグインの中の既定です。

| 決めているもの | 内容 | 変えたいときの手段 |
| --- | --- | --- |
| 接続の形 | OpenAI 互換の `chat/completions`。要求は、`model`、`temperature`、`messages`（system と user）だけ | ほかの API は、生成器を書く（[plugins/generator.md](../../plugins/generator.md)） |
| 訳し先の言語の名前の既定 | `日本語` | プラグインの設定、生成器の `options` |
| プロンプトの既定 | 日本語の文章。評価の理由も、日本語で書かせる | プラグインの設定、生成器の `options` |
| 評価の判定の値 | `OK`、`WARNING`、`NG` | 表示名と色は、列の `type`。値を変えるなら、生成器を書く |
| 返事の形 | まとめて送るときと、評価の JSON の形 | 生成器を書く |
| まとめて送る件数の既定 | 1 件ずつ | 実行のときに選ぶ |
| 同時に送る要求の数 | 2 | 生成器を書く |
| やり直しの回数 | 2 | 生成器を書く |

## 確かめていないこと

- 実際の LLM の API と、実際の LiteLLM には、接続して確かめていません。確かめているのは、`fetch` を差し替えたテストと、決まった返事を返す確認用のサーバーを相手にした実行です。
- 既定のプロンプトで、実際のモデルがどのくらい正しく判定するか、まとめて送ったときに返事の形を守るかは、確かめていません。「返事の読み方」の受け入れる形と断る形は、実際のモデルの返事を集めて決めたものではありません。
