# @loc-studio/builtin の設計

`@loc-studio/builtin` の各実装が守っている決まりと、その決まりから出てくる動きをまとめます。理由を書いた箇所は、ソースのコメントか、ほかの文書に書かれているものです。実装の細部は [implementation.md](implementation.md)、設定に書ける値は [settings.md](settings.md) にあります。

## アプリとの境目

このプラグインは、拡張ポイントの実装の 1 組です。スタジオが書くプラグインと同じ `Plugin` のオブジェクトで、同じ手順で登録されます。違うのは読み込まれ方だけで、プラグインフォルダから探すのではなく、サービス層とコマンドラインが、プロジェクトを開くときに `openProject` の `builtins` に渡します。登録される層は `builtin` です。後から読み込まれる層（アプリ、プロジェクト、個人）が同じ `id` を登録すると、そちらが使われます。

コア（`packages/core`）は、このパッケージに依存しません。コアにあるのは、設定に `tree` がないときに使う実装の `id`（`builtin.globTree`）という文字列だけです。CSV を読む処理も、ステータスを DB に置く処理も、コアの中にはありません。

アプリのコードが同梱の実装を名指ししている場所は、次の 4 つです。あとの 3 つは、[ARCHITECTURE.md の 8 章](../../ARCHITECTURE.md#8-決め打ちにしているもの)の「新しいプロジェクトの雛形」と「設定の画面で編集できる項目」に書かれている決め打ちです。

- コアの、`tree` を省略したときの既定。
- 新しいプロジェクトの雛形（`packages/server/src/new-project.ts`）。作る設定に、同梱の列、検証、CSV / TSV の列の対応を書きます。すでにあるファイルを確かめるために、このパッケージの、フォルダの走査と見出しの読み取りの関数も使います。
- 設定の画面の「CSV / TSV の列の対応」（`apps/web/lib/client/config-edit.ts`）。`builtin.csv` と `builtin.tsv` の項目の options を編集します。設定に `formats` がないときは、この 2 つの項目を足します。
- 設定の画面の列の編集（同じファイルの `defaultColumnEntries`）。設定に `columns` がないとき、既定の 2 列を、`builtin.key` と `builtin.text` を `use` で選ぶ形で書き出します。

アプリのコードは、選択肢の値（`done`、`ok` など）で分岐しません。進捗に数えるかどうかは選択肢の `complete` で、コメントが必須かどうかは `requireComment` で決まります。このため、同梱の列の選択肢を設定で置き換えても、アプリの動きは変わりません。

## プラグインの中の分け方

ツリー、フォーマット、記法、バリデータ、列ソース、列は、別々の拡張ポイントで、互いを呼び出しません。実装のファイルも、拡張ポイントごとに分かれています。ファイルをまたぐ共有は 2 つだけです。フォーマットが文字コードの読み書き（`encoding.ts`）を使い、レビューの列ソースが、名前空間のオプションを確かめる関数を DB の列ソースから使います。

この 1 組で、設定に言語だけを書いたプロジェクトを開き、フォルダの CSV を読んで、本文を編集して書き戻せます（[guide.md](guide.md#設定を書かずに使える範囲)）。LLM を使う生成器は、このプラグインには入っておらず、別のパッケージ（`@loc-studio/plugin-llm`）にあります。

## ツリー（builtin.globTree）

リソースのパスは、プロジェクトのフォルダからの相対パスです。解決した結果がフォルダの外に出るもの（`..` を含むものなど）は、読むときも書くときも断ります。この確認は、パスの文字列の上で行います。走査では、シンボリックリンクを辿らず、リソースにもしないので、リンクの先のファイルは一覧に出ません。ただし、読み書きや作成に渡されたパスの、途中のフォルダがリンクかどうかは確かめていません。

リソースの版は、ファイルの更新時刻（ナノ秒）と大きさの組です。版を確かめるだけなら、ファイルの中身を読みません。更新時刻と大きさの両方が変わらない書き換えは、この版では見分けられません。

読むときは、中身と版を、同じファイルハンドルから取ります。読んでいる途中でファイルが置き換えられても、中身と版を取り違えないためです。

書くときは、同じフォルダに一時ファイルを書いてから、名前を変えて置き換えます。途中で失敗しても、元のファイルは壊れず、一時ファイルも残しません。読んだときの版（`expectedRevision`）が渡されたときは、置き換える直前にいまの版と比べ、違えば書かずに版の競合（`RevisionConflictError`）を投げます。競合のあとで読み直して編集を当て直すのは、サービス層の役目です。版の確認と置き換えは別々の操作なので、その間に別のプロセスが書いた場合は検出できません。

新しいリソースは、すでにあるファイルを上書きしない書き方で作ります。ツリーの対象（`include` と `exclude`）に入らない場所にも作りません。作っても一覧に出ず、開けないためです。

変更の監視（`TreeProvider.watch`）は実装していません。アプリの外での書き換えは、サービス層が版を確かめ直すことで見つけます。

## フォーマット（builtin.csv、builtin.tsv）

### 変更したフィールドのほかは、1 文字も変えない

本文の正はファイルです。このフォーマットは、書き戻すときに、変更したフィールドの生のテキストだけを差し替えます。ほかの部分は、引用符の付け方、空白、改行の種類、BOM、空の行まで、読んだときのまま出します。変更がなければ、文字コードの変換もせずに、元のバイト列の写しを返します。

その結果、保存したあとのファイルを元のファイルと比べると、差は変えたフィールドだけになります。ほかのツールが付けた引用符や改行の書き方も残ります。

行を足す、消す、キーを変えるときも、ほかの行は変えません。足す行の改行は、そのファイルでいちばん多い改行に合わせます。末尾に改行のないファイルは、行を足したり消したりしても、末尾に改行のない状態を保ちます。末尾の空の行は、行を足しても末尾に残ります。

この決まりの例外は 2 つです。1 つは、見出しにない列を足すとき（下の節）です。もう 1 つは、フィールドの足りない行の、足りない位置に値を書くときで、その行に、足りない分の区切りを足します。

### 位置は、文字コードを戻した文字列の上で数える

解析は、文字コードを戻したあとの文字列の上で行い、フィールドの位置も文字列の添字（UTF-16）で持ちます。バイト列に戻すのは、最後の 1 回だけです。日本語や絵文字のように、1 文字が複数のバイトになる文字があっても、位置がずれません。

### 崩れた入力は、読めるところまで読んで知らせる

形の崩れた行があっても、ファイル全体を読めなくはしません。読めるところを読み、崩れは診断として知らせます。

| 入力 | 扱い |
| --- | --- |
| 閉じていない引用符 | ファイルの終わりまでを 1 つの値として読み、警告にする |
| 閉じ引用符の後ろの余計な文字 | 次の区切りまでを同じフィールドの値として読み、警告にする |
| キーが空の行 | 読み飛ばして、警告にする |
| キーが重複した行 | 最初の行だけを使い、後ろの行は読み飛ばして、警告にする |
| 設定にある見出しがない | その列を空として読み、警告にする |
| キーの列がない | 行を 1 つも読まず、エラーの診断にする |
| その文字コードとして読めないバイト列 | 例外にする（リソース全体が読めない） |

読み飛ばした行は、書き戻しでも元のまま残ります。行はキーで特定するので、キーの列がないファイルからは行を作れません。

### 文字コードは、書き戻して元に戻るものだけを読む

書き戻しは、読んだときの文字コードで行います。自動で見分けるのは、先頭に BOM のある UTF-16 だけで、BOM がなければ UTF-8 として読みます。Shift_JIS は、設定で指定されたときだけ使います。

Shift_JIS には、同じ文字を表すバイト列が 2 通りある文字があります（機種依存文字の重複など）。そういうファイルを読んで書き戻すと、変更していない部分のバイトが変わります。そこで、Shift_JIS として読んだ文字列をもう一度 Shift_JIS にして、元のバイト列と同じになることを、読む時点で確かめます。同じにならないファイルは、エラーにして、UTF-8 か UTF-16 への変換を案内します（黙ってバイト列を変えないためです）。Shift_JIS で表せない文字を書こうとしたときも、別の文字には置き換えず、保存を失敗にします。

### 見出しにない列は、値を書いたときに足す

設定にある列がファイルにないとき、読み込みでは空の列として扱い、空でない値を書いたときに初めて列を足します。列がない状態で空の値を書いても、読み戻した値は変わらないので、何もしません。

足し方は、設定の `addColumns` で 3 つから選べます。既定の `all-rows` は、すべての行の末尾に空のフィールドを足して、表を長方形に保ちます。`header-only` は、見出しと、値を書く行だけを変えます。`never` は、列を足さずに失敗にします。

足そうとした見出しが、すでに別の列として見出しにあるときは、足さずに失敗にします。同じ見出しが 2 つあると、読み戻しがあいまいになるためです。見出しより長い行があるファイルでは、その行の余りのフィールドと重ならない位置に列を足します。

### 新しいリソースは、設定から見出しを作る

新しいリソースの見出しは、キー、プロジェクトの言語（`text` の対応があれば、対応のある言語だけ）、`columns` の列、`stableId` の順です。キーの見出しは、設定の `key` で、なければ `key` という文字列です。

## 記法

記法は、本文を、本文の部分と、変数やタグの部分に分けます。分けた結果は、すき間なく並び、つなげると元の本文になります。これが、検証と色分けの前提です。

3 つの記法は、互いを知りません。複数の記法を重ねる処理（前の記法が本文とした部分だけを、次の記法で分ける）はコアにあり、同梱の記法は、それぞれ 1 つの書き方だけを見つけます。スタジオ固有の制御コードは、記法のプラグインを足して、`syntaxes` に並べます（[plugins/syntax.md](../../plugins/syntax.md)）。

`builtin.printf` は、`%%`（`%` そのもの）を本文として扱います。`%%s` の `s` が変数と誤認されないよう、`%%` を先に読み進めます。

## バリデータ

5 つのバリデータは、どれも 1 つのセルの本文だけを見ます（基の言語の本文は、アプリが `ctx.base` として渡します）。ほかの行と比べる検証（キーの重複、訳の揺れ）は、同梱にはありません。そういう検証は、リソース全体を受け取るバリデータとして書きます（[plugins/validator.md](../../plugins/validator.md)）。

どのバリデータも、設定の `validators` で選ぶまで動きません。重さも設定で変えられます。既定の重さは、変数とタグの過不足、タグの対応、文字数の上限が error、空白と未翻訳が warning です。

指摘には、種類を表す `code` を付けます。絞り込み（条件式の `issueCode`）と集計は、文言ではなく `code` で行います。

- `builtin.placeholders` は、変数とタグの文字列ごとに、数を比べます。順番は比べないので、変数の順を入れ替えた訳文は指摘されません。
- `builtin.untranslated` の「原文と同じ」は、原文の本文の部分に文字（Unicode の Letter）があるときだけ指摘します。数字だけ、記号だけ、変数だけの本文は、原文と同じでも指摘されません。
- `builtin.maxLength` は、既定では変数とタグを数えません。数えるのはファイル上の文字で、変数が置き換わったあとの長さや、表示の幅（全角と半角の違い、フォント）は見ません。幅での制限は、スタジオのバリデータで書きます（`examples/sample-project` の `mystudio.lineWidth` が例です）。
- 修正案（`fix`）を出すのは、`builtin.whitespace` だけです。

## 列ソース（builtin.db）

`builtin.db` は、列の値を、ホストの DB（共有 DB）の「セルごとの値」の入れ物に置きます。SQL は書かず、アプリがプラグインに見せている入れ物（`host.db.cells(名前空間)`）だけを使います。スタジオのプラグインが同じことをするときも、同じ書き方になります（[plugins/source.md](../../plugins/source.md#ホストの-db-に置く列ソース)）。

値は、変えた時点で保存します（`saveMode: "immediate"`）。本文と違って、保存の操作を待ちません。同じセルを 2 人が変えたときは、入れ物の版番号で競合を検出し、競合のエラー（`StoreConflictError`）をそのまま呼び出し側に返します。どちらの値を残すかを選ぶ画面は、アプリが出します。

行のキーが変わったら、値を新しいキーに移します。行の追加と削除では、何もしません。削除したキーを戻したときに、値も戻るほうが安全なためです。

## 列ソース（builtin.reviews）

レビューは、セルの値を書き換える操作ではなく、「列に対する投稿」です。投稿は、ホストの DB の「追記だけの記録」（`host.db.log(名前空間)`）に足し、投稿の中身は書き換えも削除もしません。行のキーが変わったときだけ、投稿とリンクの記録を、新しいキーに付け替えます。

セルの値は、最新の投稿の判定です。最新の投稿のコメントと投稿者も、値と一緒に返します（表のセルに、判定と並べて出ます）。値を直接は保存できず、保存しようとすると、投稿で変えるよう案内するエラーになります。

投稿には、その時点の対象の値（本文）の版が残ります。版を計算して渡すのはサービス層で、列ソースは受け取った版を記録するだけです。対象の値があとで変わったかどうかは、サービス層が、この版といまの版を比べて決めます。

投稿に付けるリンク（転載したチケットなど）は、投稿とは別の記録（`<名前空間>.links`）に足します。リンクを足すときも、投稿の記録には手を入れません。一覧を返すときに、投稿の ID でリンクをまとめて、投稿に添えます。

返信、解決済みの状態、添付は持ちません（[ARCHITECTURE.md の 8 章](../../ARCHITECTURE.md#8-決め打ちにしているもの)の「レビューの形」）。

## 列

登録している列は、定義の既定の値です。選択肢、表示名、色は、このプラグインの既定であって、アプリの固定値ではありません。プロジェクトは、`use` で選び、要るところだけを上書きします。

登録の `id`（`builtin.textStatus`）とは別に、プロジェクトが列の ID（`textStatus`）を付けます。列の ID は、レビュー列の `of` などの設定と、DB の記録に残る名前です。

`builtin.length` は、値を保存しない計算列です。表示する行の分だけ、本文から計算します。

## このプラグインの中で決めているもの

| 決めているもの | 内容 | 変えたいときの手段 |
| --- | --- | --- |
| 対象の拡張子 | `match` を省略したとき、`.csv` と `.tsv` | `formats` の `match` で、パスを指定する |
| 走査の既定 | `include` と `exclude` の既定 | `tree` の options |
| リソースの版 | 更新時刻と大きさ | ツリープロバイダーを書く |
| 文字コード | UTF-8、UTF-16、Shift_JIS。自動で見分けるのは BOM つきの UTF-16 だけ | ほかの文字コードは、フォーマットを書く |
| 引用符 | `"` だけ。エスケープは `""` | フォーマットを書く |
| 見出し | 空でない最初の行を、必ず見出しとして読む。空のファイルは、読むと行が 0 件で、変更できない | フォーマットを書く |
| 記法の書き方 | 3 つの記法の、それぞれの正規表現 | 記法を書いて、`syntaxes` で選ぶ |
| 文字数の数え方 | Unicode のコードポイントの数 | バリデータを書く |
| 選択肢の既定 | ステータス 3 つ、レビューの判定 4 つ | 列の `type` を上書きする |
| 名前空間の既定 | `builtin.db`、`builtin.reviews` | `sources` の options |
| 文言 | 日本語 | なし |
