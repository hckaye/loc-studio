# はじめに

リポジトリを取得してから、サンプルプロジェクトの本文を画面で編集するまでの手順です。ここで説明するのは、1 人が自分の PC で使うローカルモードです。複数人で 1 つのサーバーを使う Web モードは [WEB-MODE.md](WEB-MODE.md) にあります。

画面の操作の説明は、`apps/web` のコードを読んで書いています。ブラウザで操作して確かめた記録ではないので、実際の表示と違う点があれば、コードを正としてください（確かめた範囲は「確かめたこと」の節にあります）。

## 1. 導入とビルド

必要なもの: Node.js 22.13 以上（`node:sqlite` を使います）。

```sh
npm install
npm run build    # tsc -b。packages/* と apps/cli を dist/ に出力する
```

`npm run build` は画面（`apps/web`）とデスクトップ（`apps/desktop`）をビルドしません。画面は実行時に `packages/*/dist` を読み込むので、画面を動かす前に必ず `npm run build` を済ませてください。

コマンドラインで動作を確かめます。

```sh
cp -r examples/sample-project /tmp/sample-project
node apps/cli/dist/index.js tree --project /tmp/sample-project
```

```
SampleGame/
  Assets/
    Text/
      system/
        ui.csv  4 件  [builtin.csv]
      chapter01.csv  8 件  [builtin.csv]
```

プロジェクトのフォルダをコピーして使うのは、編集すると CSV が書き換わり、ステータスなどを置くデータベースが `<プロジェクト>/.loc-studio/meta.db` に作られるためです。`plugins` / `tree` / `validate` / `whoami` はデータベースを作りませんが、`status` / `set` / `save` / `generate` / `run` と画面は作ります。

## 2. 画面を起動する

画面は Next.js で、サービス層（`packages/server`）を呼ぶ薄い層です。サーバーは `npm run start:web`（本番）か `npm run dev:web`（開発）で起動します。どちらも起動の仕組み（`apps/web/scripts/launch.mjs`）を通り、設定を確かめてから Next.js のサーバーを動かします。standalone の `server.js` を直接起動しないでください（起動の合言葉がないため、すべての要求に 500 を返します）。起動は環境変数で設定します。

| 環境変数 | 意味 |
| --- | --- |
| `LOC_STUDIO_PROJECT` | 起動時に開くプロジェクトのフォルダ（`loc-studio.project.json` のあるフォルダ）。省略すると「プロジェクトを開く」画面が出ます |
| `LOC_STUDIO_USER_DATA_DIR` | 個人の設定フォルダ。ローカル設定 `settings.json`、その PC の DB（`projects/<ハッシュ>/local.db`）、個人のプラグインフォルダ `plugins/`、最近開いたプロジェクトの一覧 `web-session.json` を置きます。省略すると、ローカル設定ファイルのあるフォルダ（Linux は `~/.config/loc-studio`）になります |
| `LOC_STUDIO_APP_DIR` | アプリのフォルダ。その中の `plugins/` を、アプリ層のプラグインフォルダとして読みます |
| `PORT` | 待ち受けるポート。既定 3000 |
| `LOC_STUDIO_HOST` | 待ち受けるアドレス。既定 `127.0.0.1`。ローカルモードでループバック以外のアドレスにするには、`LOC_STUDIO_ALLOW_REMOTE_LOCAL=1` も要ります。環境変数 `HOSTNAME` は見ません |
| `LOC_STUDIO_LOCAL_TOKEN` | ローカルモードの起動の合言葉（16 文字以上）。省略すると起動のたびに作ります |

`LOC_STUDIO_MODE=web` を付けると Web モードになります（[WEB-MODE.md](WEB-MODE.md)）。そのほかの環境変数は [CONFIG.md](CONFIG.md#環境変数) にまとめています。

Windows の PowerShell では `$env:LOC_STUDIO_PROJECT = "C:\work\sample-project"` のように設定してから `npm run ...` を実行します。この手順は Windows では確かめていません。

### 開発モード

```sh
LOC_STUDIO_PROJECT=/tmp/sample-project \
LOC_STUDIO_USER_DATA_DIR=/tmp/loc-studio-user \
npm run dev:web
```

`next dev` が起動します。開く URL は、本番モードと同じく起動時に表示されます（下記）。

### 本番モード

```sh
npm run build:web     # tsc -b のあと next build（standalone 出力）と静的ファイルのコピー
LOC_STUDIO_PROJECT=/tmp/sample-project \
LOC_STUDIO_USER_DATA_DIR=/tmp/loc-studio-user \
PORT=3000 \
npm run start:web     # node apps/web/scripts/launch.mjs（standalone の server.js を起動する）
```

起動すると、ターミナルに次の形で URL が表示されます。

```
loc-studio: http://127.0.0.1:3000/?token=oUUlyJicfD_sYq5soOLaDiOnERXa4ZfRp8QUawWq4NM
（この URL から開いてください。URL はほかの人に教えないでください）
```

### 開く URL と起動の合言葉

ローカルモードでは、表示された `?token=…` 付きの URL をブラウザで開きます。サーバーは合言葉をクッキー（`HttpOnly`、`SameSite=Strict`、名前にポート番号を含む）に換え、合言葉を消した URL（`http://127.0.0.1:3000/`）に移します。以後のページと API は、このクッキーがあるときだけ応えます。合言葉は起動のたびに変わる（`LOC_STUDIO_LOCAL_TOKEN` で決めた場合を除く）ので、サーバーを起動し直したら、新しく表示された URL から開き直します。

合言葉なしで `http://127.0.0.1:3000/` を開くと、「loc-studio を開くには」のページ（HTTP 401）が出て、起動したターミナルに表示された URL から開くよう案内します。API は 401 と `{"error":{"code":"unauthorized",…}}` を返します。ほかのサイトのリンクから開いた場合も、クッキーが `SameSite=Strict` なので、このページになります。

`LOC_STUDIO_LOCAL_TOKEN=off` にすると合言葉を使いません。開発のためだけのもので、起動時に警告が出ます。ループバックで待ち受けるときだけ使え、Web モードでは使えません。合言葉がないと、この PC のほかのプログラムやユーザーも画面と API を使えます。

`npm run smoke:web` は、本番ビルドを一時コピーのプロジェクトに対して起動し、API を呼んで確かめるスクリプトです（先に `npm run build:web` が要ります）。

### ローカルモードの注意

ローカルモードには利用者ごとの認証がなく、守りは起動の合言葉だけです。合言葉付きの URL を知っている人は、プロジェクトのファイルを書き換え、プラグインのコードを実行できます。起動したターミナルの表示（スクロールバック）にも URL が残るので、画面を共有するときなどは気をつけてください。

サーバーはほかに次のことを確かめます。

- `Host` ヘッダーが、ループバックの名前（`localhost`、`127.` で始まる数字のアドレス、`[::1]`。`app.localhost` のような下の階層の名前は含みません）か、`LOC_STUDIO_ALLOWED_HOSTS`（カンマ区切り）に書いた名前であること。違えば 421 を返します。
- 状態を変える要求で、`Sec-Fetch-Site` があれば `same-origin` であること、`Origin` があれば `Host` と同じであること。違えば 403 を返します。どちらのヘッダーもない要求（`curl` などブラウザ以外の道具）は、合言葉のクッキーがあれば通します。

ほかの PC から届くアドレスで待ち受けるのは、`LOC_STUDIO_HOST` と `LOC_STUDIO_ALLOW_REMOTE_LOCAL=1` を両方設定したときだけです。その場合も合言葉は必要です。

合言葉のクッキーは、ブラウザの仕様で、同じ PC の `127.0.0.1` のほかのポートで動いているサーバーにも送られます（クッキーはポートを区別しません）。そのサーバーのページからの要求は上の確かめで断りますが、そのサーバーのプログラム自体は合言葉を読めます。信頼できないプログラムを同じ PC で動かしているときは、このことを前提にしてください。

複数人で使う方法は 2 つあります。1 つは、各自が自分の PC でローカルモードを動かし、共有 DB（[CONFIG.md の storage](CONFIG.md#storage)）だけを共有する方法です。もう 1 つは、Web モードのサーバーを 1 つ立て、各自がブラウザでログインして使う方法です（[WEB-MODE.md](WEB-MODE.md)）。

## 3. 画面の見方

起動した URL を開くと、設定ファイルに基盤の項目（`tree`、`formats` など）か環境変数の参照があるプロジェクトでは、初めて開いたときに、まず設定の確認のダイアログが出ます（[設定とプラグインの信頼](#設定とプラグインの信頼)）。信頼すると、プロジェクトが開き、左のツリーの最初のリソースが選ばれます。プロジェクトを自動で開くのは、サーバーを起動した人が決めた `LOC_STUDIO_PROJECT` だけです。なければ、フォルダのパスを入力する「プロジェクトを開く」画面が出ます（最近開いたプロジェクトの一覧つき。デスクトップ版ではフォルダ選択ボタンも出ます）。`?project=` の付いた URL を開いても、その値は「プロジェクトを開く」の入力欄に入るだけで、「開く」を押すまでプロジェクトは開きません。

### 全体

- 上のバー: プロジェクト名、「別のプロジェクト」、ユーザー名、「横断検索」、「すべて保存」、ジョブ、「プラグイン」、設定（歯車）。
- 左: リソースのツリー。
- 右: ツールバー、表、必要なら詳細パネル。
- 下のステータスバー: 行数、選択中のセル、共有 DB かローカル DB か、警告とエラーの件数。

### ツリー

- 「名前で絞り込む」で、リソースを名前で絞り込めます。フォルダは折りたためます。
- 未保存の変更があるリソースには `●件数` が付きます。
- 進捗のバーとパーセントは、最初のレビュー列（なければ最初の選択式の列）の `complete` の選択肢の割合です。ツリーの上に「進捗: ○○」と、どの列かが出ます。サンプルプロジェクトでは「レビュー」列の「承認」の割合です。裏で少しずつ集計するため、出るまで少しかかります。進捗に使う列は、設定の `grid.progressColumn` で選べます。行数ではなく、原文の文字数や語数で数えるには、設定の `grid.progressUnit` を使います。バーにマウスを載せると、数と、数えている単位（行、文字、語）が出ます。
- 検証の error があるリソースには、件数が出ます。
- 絞り込みの欄の右の「＋」で、新しいリソースを作れます（場所を拡張子まで書きます。見出しだけのリソースができます）。ツリーとフォーマットが作成に対応しているときだけ使えます。
- 進捗のバーにマウスを置くと、言語ごとの `complete` の件数と割合が出ます。

### 表

- 1 行が 1 エントリです。列は「共通のグループ」（キーなど、行に 1 つの列）と、言語ごとのグループ（その言語の本文と、その言語の列）に分かれます。
- 共通のグループは左端に固定され、横にスクロールしても動きません。言語のグループは、見出しの 📌 で左側に固定できます。`languages[].pinned` が `true` の言語は、最初から固定されます。列 ID の配列を書いた言語は、挙げた列だけが固定され、残りの列は横にスクロールします。`grid.pinCommon: false` にすると、共通のグループも横にスクロールします。固定した列の幅の合計が、表の幅の `grid.maxPinnedRatio`（既定 0.6）を超えると、後ろの固定が一時的に外れ、ステータスバーに「固定を一時解除」と出ます。
- 見出しの × で、その言語を隠します（少なくとも 1 つは表示します）。
- 列の幅は、列見出しの右端の境界をドラッグして変えます。キーボードでは、Tab で境界にフォーカスを移し、← / → で 16 ピクセルずつ（Shift を併用すると 4 ピクセルずつ）変え、Home で既定の幅に戻します。
- 表示する言語、固定、列の幅、表示密度、詳細パネルの開閉は、プロジェクトごとにブラウザの `localStorage` に覚えます。別のブラウザや PC には引き継がれません。
- 行と列の両方向を仮想化しています。表示中の言語の分だけ、行をページ単位で読み込みます。
- キーボード: 矢印、PageUp / PageDown、Home / End（Ctrl を併用すると先頭と末尾）、Tab。Shift を併用した上下で、行を範囲選択します。Enter または F2 で、セルを編集します。

### 言語の切り替え

ツールバーの「言語 3 / 16」のようなボタンで、言語の選択パネルが開きます。

- 検索（名前、ID、グループ）、グループごとの折りたたみと「すべて表示 / すべて隠す」、「すべて」「なし」。
- 表示セット: プロジェクト設定の `languageSets`（名前の後ろに ★）と、自分で保存したセット（ブラウザに保存）。
- 言語ごとの表示チェックと、左に固定する 📌。「適用」で表に反映します。

何も選んでいない初回は、言語の最初の 8 つを表示します。

### 絞り込みと検索

- 検索（Ctrl+F）: キーと、表示中の言語の本文の部分一致（大文字小文字を区別しません）。開いているリソースの中だけを探します。
- プロジェクト全体の検索（上のバーの検索ボタン、Ctrl+Shift+F）: すべてのリソースのキーと本文を探し、ヒットを選ぶとそのセルへ移ります（矢印と Enter でも選べます）。
- 再読み込み（ツールバー）: 開いているリソースを、外部の変更を含めて読み直します。
- 選択式の列ごとの絞り込み（ステータスなど）。文字や数値の列（メモ、文字数など）は、「この文字を含む」で絞り込めます。
- 「未翻訳のみ」「問題あり」「要確認」「未保存」。「問題あり」を押すと、数える重さ（エラー以上、警告以上、情報以上）を選べます。既定は警告以上です。本文以外の列の検証の問題も数えます。
- 「行」のメニュー: 行の追加（選択中の行の後ろ）、キーの変更（1 行を選んで）、選択した行の削除。どれも、確定するとすぐリソースに書きます。キーを変えると、ステータス、レビュー、履歴、未保存の編集は新しいキーに引き継がれます。行を消しても、ステータスなどの記録は残り、同じキーの行を足し直すと戻ります。
- 並べ替え: 列の見出しを押すと、その列の昇順、もう一度押すと降順、3 回目でリソースの中の順に戻ります。数値は数の順、選択式の列は選択肢の並び順で、値のない行は最後に並びます。リソースを切り替えると、リソースの中の順に戻ります。
- 表示密度（1 / 3 / 5 行）、「詳細」（詳細パネルの開閉）、「保存」。

### 本文の編集

本文のセルは、その場では編集しません。ダブルクリック、または Enter / F2 で、編集のモーダルが開きます。

- 左の「参照」: 基になる言語（`basedOn`）の本文と、生成列の値。設定の `editor` で、ほかの言語（中継の言語）や、列（備考、文字数の上限など）を足せます。基の本文の変数とタグには色が付き、「原文の変数・タグ」のボタンを押すと、編集中の本文のカーソルの位置に入ります（本文にまだない変数は、色を変えて示します）。
- 右の編集欄: 文字数、検証結果（クリックすると該当箇所を選択）。Enter は改行です。検証結果は、入力が止まってから約 0.25 秒後に、入力中の本文に対して更新します（保存はしません）。範囲を持つ検証結果は、編集欄の本文に重さごとの色の下線で示します。下線は、検証が済んだ本文と編集欄の本文が同じときだけ出し、IME で変換している間は出しません。
- 「変更を取り消す」: このセルの未保存の変更を、保存済みの値に戻します（ほかの言語の未保存の変更は残ります）。
- 下: その言語の列（ステータス、レビューなど）。
- 確定は Ctrl+Enter、確定して次の行へは Alt+↓（前の行へは Alt+↑）、取消は Esc（変更があれば破棄の確認が出ます）。
- 基になる言語の本文が、最後の編集のあとで変わっている場合は「要確認: 基の本文が変わりました」と出ます（設定の `validation.recheck` を `false` にすると出ません）。`editable: false` の言語は編集できず、「この言語は編集できない設定です」と出ます（表の言語の見出しには「読取専用」の印が付きます）。

### 保存

モーダルで確定した本文は、まず未保存の変更（ドラフト）になり、表に「未保存」の印が付きます。ドラフトはその PC の DB に退避されるので、アプリを閉じても残ります。リソースに書くのは保存操作のときです。

- 「保存」ボタンまたは Ctrl+S: 開いているリソースの未保存の変更を書きます。
- 「すべて保存」または Ctrl+Shift+S: すべてのリソースを書きます。
- 保存の前に、ファイルが外部で書き換えられていないか確かめます。書き換えられていたら読み直してからドラフトを当て直し、同じセルが食い違っていた分だけを書かずに残します。残った分は「保存できなかった変更」のダイアログに並び、セルごとに「自分の変更を使う」（自分の値を保存）か「リソースの値を使う」（ドラフトを捨てる）を選べます。閉じても、未保存の変更は残ります。
- 未保存の変更の取り消し: ツールバーの「取り消す」で、開いているリソースの未保存の変更をすべて取り消します（確認が出ます。元に戻せません）。詳細パネルの「変更を取り消す」では、その行の分だけ取り消します。
- 編集モーダルを開いている間の Ctrl+S は、先に確定（Ctrl+Enter）するよう通知が出るだけで、保存はしません。

### ステータスの選択（選択式の列）

選択式の列（既定では「テキスト」のステータスと「レビュー」）は、セルのドロップダウンで選びます。選択肢、色、進捗に数える選択肢は、列の定義から来ます。

- ステータスの変更は、保存操作を待たずに、変えた瞬間に共有 DB（既定では `.loc-studio/meta.db`）へ書かれます。変更履歴に残ります。
- ほかの人が先に同じセルを変えていた場合は、「ほかの人が先に変更しました」のダイアログが出ます。いまの値（変えた人と時刻つき）と自分の値を見比べて、「いまの値を使う」か「自分の値で上書き」を選びます。
- `validation.blockComplete` を設定していると、本文に問題が残る言語を、`complete` の選択肢（「確定」など）に変えようとしたときに止められます。
- 選択肢に `from` や `roles` を設定していると、いまの値から変えられない選択肢や、自分の役割では選べない選択肢は、理由つきで選べなくなります（[CONFIG.md の列挙の選択肢](CONFIG.md#列挙enumの選択肢)）。
- 複数行を選ぶと「N 行を選択中」のバーが出て、選択した行の選択式の列を一括で変えられます（アクションや生成の一括実行もここから）。

### レビューの投稿

レビュー列（`kind: "review"`）は、ドロップダウンで判定を選ぶと、投稿のパネルが開きます。

- 判定を選び、コメントを書いて「投稿」（コメント欄で Ctrl+Enter でも投稿）。`requireComment` が付いた判定（既定では「差し戻し」）はコメントが必須です。
- 投稿には、その時点の対象（本文）の版と、ユーザー名が残ります。あとで本文が変わると、その投稿に「変更あり」の印が付きます。
- 「これまでの投稿」の一覧、「この時点の値と比べる」（その時点の本文との差分）、リンク（転載したチケットなど）。プラグインが返したリンク（レビューのリンク、`display: "link"` の列、アクションの結果）は、`http` か `https` の URL のときだけクリックでき、それ以外は文字として出ます。
- レビュー先（設定の `review.targets`）があれば、投稿をレビュー先へ転載できます。ローカル設定 `review.forwardOnPost` が `always` なら自動、`ask`（既定）なら投稿のたびにチェックボックスで選び、`never` なら投稿時には転載しません。投稿済みの投稿には「○○に転載」のボタンが出ます。

### 詳細パネル

ツールバーの「詳細」で開きます。選択した行の、共通の列、全言語の本文と検証結果、レビューの投稿（言語を選んで見る）、変更履歴（誰が・いつ・何を・何から何へ）が出ます。行に未保存の変更があれば「変更を取り消す」も出ます。

### 生成列とアクション

- 生成列（`kind: "generated"`、逆翻訳など）: セルに「最新 / 古い / 未生成」の印と、生成のボタン（「⟳」。マウスを置くと「生成」と出ます）が出ます。範囲（このセル、選択した行、このリソース全体、プロジェクト全体）を選ぶダイアログが出て、全体・キャッシュ済み・実行する件数が見えます。
- アクション列（`kind: "actions"`）: アクションのボタンが並びます。
- アクションの対象が列（`target: "column"`）のものは列見出しの「⋮」メニュー、ファイル（`target: "file"`）のものはツールバーの「アクション ▾」メニューから実行します。
- 計算列（`kind: "computed"`、同梱では `builtin.length` の「文字数」）は読み取り専用で、保存されません。
- 実行中のジョブは、上のバーの「ジョブ」で進み具合を見て、取り消せます。

### 設定

上のバーの歯車です。「プロジェクト設定」と「ローカル設定」（Web モードでは「個人設定」）の 2 つのタブがあります。

- プロジェクト: プロジェクト名、言語の一覧（表示のみ。言語の追加や変更は設定ファイルで行います）、共有 DB の場所（`storage.path`）と共有の方式、使っているバリデータ（表示のみ）、プラグインフォルダ（`pluginDirs`）。保存先の `loc-studio.project.json` が書き換わり、設定とプラグインが読み直されます。読み直せない設定は、元に戻されて、エラーが出ます。`loc-studio.config.ts` で決まっている項目には印が付き、画面からは変えられません。
- ローカル: ユーザー名（「PC 名に戻す」のボタンで、PC 名に戻せます）、テーマ（ライト / ダーク / OS に合わせる）、レビュー先への転載。プロジェクト設定で固定された項目は、変更できないと表示されます。ほかの設定キーも「そのほかの設定」に並びます。

### プラグインのダイアログ

上のバーの「プラグイン」です。読み込んだプラグイン（名前、層、提供するもの）、探したフォルダ（後ろほど優先。あるかどうか）、読み込みエラーと警告が見えます。「プラグインを再読み込み」で、プラグインフォルダと設定を読み直します（アプリの再起動は要りません）。プラグインを書いている間は、これで確かめます。

#### 設定とプラグインの信頼

画面では、プロジェクトを開いても、利用者が確認するまで次の 3 つを使いません。

- プロジェクトの設定ファイル（`loc-studio.project.json`）の基盤の項目。データの保存先、プラグインのフォルダ、外部の接続先、使う環境変数を決める部分です。
- プロジェクトのコードの設定（`loc-studio.config.*`）。
- プロジェクトのフォルダ（project 層）とこの PC の個人のフォルダ（local 層）にあるプラグイン。

コードは読み込まれるとあなたと同じ権限で動き、設定ファイルは書かれた接続先へこの PC から接続させるためです。同梱とアプリ層のプラグインは、確認なしで読み込みます。コマンドラインは、どれも確認なしで使います。

設定ファイルに基盤の項目か環境変数の参照があるプロジェクトを初めて開くと、「このプロジェクトの設定を信頼しますか」のダイアログだけが出ます（表もツリーもまだ読みません）。コードの設定（`loc-studio.config.*`）もまだ信頼していないプロジェクトでは、設定ファイルとコードの設定が同じダイアログに並び、題は「このプロジェクトの設定とコードを信頼しますか」になります。どちらもない設定ファイルでは、この確認は出ません。ダイアログには、設定ファイルのパス、内容の要約、確認の対象のファイル、ハッシュの先頭が出ます。要約には基盤の項目がすべて並びます。保存先（共有 DB）、参照する環境変数の名前、プラグインのフォルダ、ツリー、フォーマット、記法、列ソース、生成器、アクション、レビュー先の 1 つ 1 つと、その options の値を 1 行ずつ、「生成器 backTranslation の options.endpoint」のような項目のパスで出します。値は設定ファイルに書かれたままの形（文字列は引用符つき）で出ます。環境変数は展開せず、接続文字列のパスワードは `****` に伏せます。

要約は、接続先を見落とさないようにできています。

- 値が URL として読めるときは、その行に「接続先」として、実際に接続するホストとポートが出ます。`https://good.example@evil.example` のような書き方でも、接続先には `evil.example` が出て、ユーザー情報の部分があるという注意が付きます。表の上には「この設定で接続する先:」として、接続先がまとめて並びます。
- Postgres の接続文字列（`postgres:`、`postgresql:`、`socket:`）では、ドライバーと同じ決め方で接続先を出します。`postgres://user@db.good.example:5432/loc?host=127.0.0.1&port=9988` の接続先は `127.0.0.1:9988` です。クエリの `host`、`hostaddr`、`port`、`sslrootcert`、`sslcert`、`sslkey`、`options`、`service`、`target_session_attrs` は、「共有 DB の url の ?host」のような別の行にも必ず出ます。ホストやポートの指定がないときは既定の `localhost:5432` を出し、環境変数 PGHOST / PGPORT で変わることがあるという注意を付けます。
- 接続先やパスが環境変数で決まる値には、その環境変数の名前を示す注意が付きます。
- 文字の向きを変える制御文字などは `<U+202E>` のような形で出ます。500 文字を超える値は、省いた文字数を示して切ります。1 つの項目の options が 40 を超えるときは、最初の 40 行と残りの数を出し、残りのうち URL、パス、環境変数を含む値は必ず出します。
- 秘密情報の名前らしい項目名（`apiKeySecret` など）には、値がこの PC のローカル設定にあるという注意が付きます。
- ツリー、生成器、アクション、列ソース、レビュー先のどれかがあるときは、最後の行に、これらの実装がこの PC の秘密情報を読んで上の接続先へ送ることがあると出ます。

選べるのは「信頼して開く」（コードの設定も並んでいるときは「信頼して読み込む」）と「プロジェクトを閉じる」です。プロジェクトは設定がないと動かないので、設定を読み込まずに開くことはできません。

設定を信頼すると、プロジェクトを開き直します。プロジェクトにプラグインがあれば、続けて「このプロジェクトのプラグインを実行しますか」のダイアログが出ます（上に「設定を信頼しました。続けて、このプロジェクトのコードを確認します。」と出ます）。こちらには、プラグインやコードの設定がまとめて並び、それぞれ種類、層、パス、確認の対象のファイル（6 つを超えると折りたたむ）、ハッシュの先頭が出ます。「信頼して読み込む」か「読み込まずに開く」を選びます。読み込まなくても、本文の編集と保存はできます（プラグインが提供するバリデータ、列、アクションなどは使えません）。

- 読み込んでいないプラグインがある間は、画面の上に警告の帯が出て、そこからダイアログを開き直せます。
- 「プラグイン」のダイアログには、未信頼のプラグインの一覧と、プラグインごとの「信頼する」「信頼を取り消す」のボタンがあります。
- 信頼は、中身のハッシュごとに、この PC のローカル設定 `plugins.trust` に記録されます。プラグインやコードの設定のファイルが変わると、もう一度確認します。設定ファイルは、基盤の項目が変わったときだけ、もう一度確認します。言語や列などの変更では確認しません。画面の設定のダイアログから自分で変えた場合も、変える前の内容が信頼済みなら確認しません。
- ダイアログを出したあとで中身が変わっていた場合は、ダイアログが一覧を読み直し、もう一度確かめるよう求めます。
- 作業の途中で、設定ファイルの基盤の項目やコードの設定がアプリの外で変わる（git の更新など）と、次に設定を読み直したとき（「プラグインを再読み込み」など）に、確認のダイアログに切り替わります。表の画面は後ろに残っていて、信頼すると元の画面に戻ります。保存していない変更と、開いていた編集欄の入力は残ります。
- コードの設定を信頼していない間は、`loc-studio.project.json` だけで開きます。JSON だけでは設定として足りないプロジェクト（設定を `loc-studio.config.ts` だけに書いたプロジェクトなど）は、信頼するまで開けません。画面には「このプロジェクトのコードを実行しますか」のダイアログだけが出て、選べるのは「信頼して読み込む」と「プロジェクトを閉じる」です。
- 信頼の確認をするプラグインとコードの設定は、import の書き方と import できるものに条件があります。条件に合わないものは、信頼の候補にも出ず、読み込みエラーになります。詳しくは [plugins/trust.md](plugins/trust.md)。設定ファイルの確認の詳細は [CONFIG.md の「設定ファイルの確認」](CONFIG.md#設定ファイルの確認画面のローカルモード)にあります。

## 4. デスクトップ版

`apps/desktop` は、Web アプリの standalone ビルドを `127.0.0.1` の空きポートで子プロセスとして起動し、`BrowserWindow` に表示する Electron の殻です。起動のたびに起動の合言葉を作ってサーバーに渡し、ウィンドウは合言葉付きの URL を開くので、利用者が URL をコピーする必要はありません。

```sh
npm run build:web       # 先に Web アプリをビルドする（自動では行われない）
npm run build:desktop   # tsc で apps/desktop/dist へ
npm run start:desktop   # electron .  （フォルダを引数に渡すと、そのプロジェクトを開く）
```

- プロジェクトの指定は、コマンドライン引数、なければ前回開いたプロジェクトです。メニュー「ファイル > プロジェクトを開く…」（Ctrl+O）は、選んだフォルダのパスを `?project=` に付けて、画面を読み込み直します。画面は `?project=` の値を「プロジェクトを開く」の入力欄に入れるだけなので、コードの上では、「開く」を押すまで開きません。起動時にプロジェクトを指定していた場合は、読み込み直しで、起動時のプロジェクトが開き直ります。
- 個人の設定フォルダは Electron の `userData` です（メニュー「ヘルプ > 設定フォルダを開く」）。
- アプリ層のプラグインフォルダは、配布物の隣の `plugins` です（メニュー「ヘルプ > プラグインフォルダを開く」）。開発時は `apps/desktop/plugins` です。
- 配布物の作成は `npm run build:web && npm run dist:desktop` です。

`apps/desktop/package.json` は Electron `^45.3.0` を指定しています。同梱の Node の版（`node:sqlite` には 22.13 以上が要ります）は確かめていません。

Electron の実行ファイルを取得できる環境で試していないため、Electron の起動、ウィンドウ、メニュー、フォルダ選択、`ELECTRON_RUN_AS_NODE` での `node:sqlite` の動作、electron-builder による配布物の作成（署名を含む）は、一度も実行していません。確認できているのは、`tsc` が通ることと、`apps/desktop` のテスト（空きポート、パスの解決、環境変数の許可リストとコマンドの組み立て、起動待ち、メニュー、standalone の `launch.mjs` を実際に起動して合言葉の扱いを確かめるテスト）です。詳しくは [apps/desktop/README.md](../apps/desktop/README.md) にあります。

## 5. プロジェクトを一から作る

プロジェクトのフォルダに `loc-studio.project.json` を置けば、プロジェクトとして開けます。次は、CSV を扱う最小の構成です。

```
my-game/
  loc-studio.project.json
  Text/
    ui.csv
```

`Text/ui.csv`:

```csv
ID,JP,EN,MaxLen
UI_OK,決定,OK,4
UI_CANCEL,キャンセル,Cancel,6
UI_GOLD,所持金：{gold} G,Gold: {gold} G,
```

`loc-studio.project.json`:

```json
{
  "name": "MyGame",
  "languages": [
    { "id": "ja", "label": "日本語", "pinned": true },
    { "id": "en", "label": "英語", "basedOn": "ja" }
  ],
  "tree": { "use": "builtin.globTree", "options": { "include": ["Text/**/*.csv"] } },
  "formats": [
    {
      "use": "builtin.csv",
      "match": "**/*.csv",
      "options": {
        "key": "ID",
        "text": { "ja": "JP", "en": "EN" },
        "columns": { "maxLength": "MaxLen" }
      }
    }
  ],
  "syntaxes": ["builtin.braces", "builtin.tags"],
  "columns": [
    { "use": "builtin.key", "id": "key" },
    { "use": "builtin.text", "id": "text" },
    { "use": "builtin.textStatus", "id": "textStatus" },
    { "use": "builtin.reviewStatus", "id": "reviewStatus", "of": "text" }
  ],
  "validators": [
    "builtin.placeholders",
    "builtin.tagBalance",
    "builtin.maxLength",
    "builtin.untranslated"
  ]
}
```

設定の各部分の意味は次のとおりです。各キーの詳細は [CONFIG.md](CONFIG.md) を参照してください。

- 必須なのは `languages` だけです。言語の ID は任意の文字列で、標準のロケール名である必要はありません。`basedOn` を持たない言語が原文の扱いです。
- `formats[].options.text` は、言語 ID から CSV の見出しへの対応です。省略した言語は、言語 ID と同じ見出しの列を本文とみなします。見出しにない列は、その言語の本文を保存したときに足されます（[CONFIG.md の formats](CONFIG.md#formats)）。`options.columns` の `maxLength` は、`builtin.maxLength` が文字数の上限を読む場所です（行ごとの上限）。
- `columns` の `builtin.text` と `builtin.key` は、本文とキーの列です。`id` に短い名前を付けると（`key`、`text` など）、セル ID（`textStatus@ja` など）や DB の記録に、その名前が使われます。`reviewStatus` の `of` は、レビューの対象の列（ここでは本文の列の id）です。
- `columns` を省略すると、「キー」「本文」の 2 列だけになります。ステータスやレビューの列は、`use` で選んだときだけ出ます。
- 設定を間違えても、プロジェクトは開きます。登録されていない実装の指定などは、下のステータスバーの警告（「警告とエラー」）に出ます。ただし `languages` がない、`basedOn` が循環している、といった設定の形の誤りは、プロジェクトを開けません。

動作を確かめます。

```sh
node apps/cli/dist/index.js tree     --project my-game
node apps/cli/dist/index.js validate --project my-game
LOC_STUDIO_PROJECT=$PWD/my-game npm run dev:web
```

この最小の構成（上の CSV と設定）は、一時フォルダに作って、CLI の `tree` / `validate` / `status` が通ることを確かめました（`validate` は問題 0 件、`status` は 3 エントリ）。画面での表示は確かめていません。
